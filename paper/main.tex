\title{Keys Decide, Values Describe: Sensitivity-Aware KV Cache Compression for Speculative Decoding}

\author{Anonymous authors}

\begin{document}

\maketitle

\begin{abstract}
Speculative decoding accelerates language-model inference by asking a small draft
model to propose tokens for verification by a larger target model, but standard
implementations retain a separate key--value (KV) cache for each model. We study
how the draft cache can be compressed while preserving the quantity that directly
controls speculative speed: token acceptance. Our central observation is that
acceptance is strongly asymmetric in key and value precision. Across six
target--draft pairs, held-out text, mathematics, and code prompts, and contexts
up to 32K, 8-bit
keys with 4-bit values (K8V4) outperform the equal-memory K4V8 assignment in
19 of 20 matched comparisons. On Qwen2.5-3B/1.5B, K8V4 improves acceptance by
0.312 at 1K and 0.336 at 4K while reducing total target-plus-draft KV memory by
27.0\%. Controlled Gaussian perturbations expose the same mechanism: key noise
changes attention routing and rapidly destroys top-1 stability, whereas value
noise is tolerated at much larger magnitudes. Based on this observation, \method
profiles each draft layer and cache component under both ordinary language-model
quality and the actual speculative loop, then cross-evaluates equal-memory mixed-
precision allocations. The two objectives produce different sensitivity maps,
but acceptance-optimized allocation does not consistently outperform the simpler
quality-trained K-first policy on held-out prompts. The target verifier is never
quantized; we separately audit finite-precision differences between batched
verification and tokenwise BF16 decoding.
\end{abstract}

\section{Introduction}

Speculative decoding converts several serial target-model decoding steps into a
single parallel verification step by sampling proposals from a cheaper draft
model~\citep{leviathan2023speculative,chen2023speculative}. The method is
distribution preserving, but its systems footprint includes two model states and
two growing KV caches. This duplication becomes consequential at long context,
where each generated token reads the prefix cache and cache capacity limits the
number of concurrently served requests.

Quantizing the draft cache seems straightforward, but generic model-quality
metrics do not reveal whether a compressed cache remains a useful speculator. A
small distributional error can move the draft's top proposal away from the
target's token and terminate an entire speculative block. Conversely, errors in
directions irrelevant to the verifier may have little effect on acceptance. This
motivates measuring compression inside the speculative loop and testing whether
an acceptance-aware objective improves upon ordinary language-model quality.

Our investigation starts from the attention decomposition
\begin{equation}
  A_\ell = \operatorname{softmax}\!\left(\frac{Q_\ell K_\ell^\top}{\sqrt{d_h}} + M\right),
  \qquad O_\ell = A_\ell V_\ell W_{O,\ell}.
  \label{eq:attention}
\end{equation}
Keys determine the routing distribution $A_\ell$, whereas values determine the
payload read after routing. We hypothesize that coarse key quantization is more
likely to redirect attention and cascade through subsequent layers than an
equal-memory reduction in value precision. This role asymmetry is compatible with
prior KV quantization analyses~\citep{liu2024kivi,hariri2025more}, but we ask a
different operational question: \emph{which errors can a draft model tolerate
without losing speculative acceptance?}

Our findings support four claims. First, Gaussian key perturbations
are dramatically more destructive to next-token stability than value
perturbations. Second, K8V4 dominates K4V8 in 19 of 20 equal-memory comparisons
across six model pairs; the only reversal is an OLMo difference of $-0.002$ whose
confidence interval includes zero. Third, a conservative layer-wise allocator
retains 94.9--102.8\% of native acceptance while saving 2.9--9.9\% of total KV
memory. Fourth, directly fitting the allocator to speculative acceptance changes
its selected precision map but does not consistently improve held-out acceptance;
the stable result is the K/V asymmetry itself, not superiority of one profiling
objective.

\section{Background and Problem Formulation}

Let $p(\cdot\mid x_{\le t})$ be the target distribution and
$q(\cdot\mid x_{\le t};\widehat{\mathcal C}_d)$ the draft distribution produced
from a compressed draft cache $\widehat{\mathcal C}_d$. Standard speculative
sampling accepts proposals using the target correction rule; greedy speculative
decoding accepts the longest proposal prefix matching target argmax tokens. In
both cases, target verification is distribution preserving in exact arithmetic:
compression affects efficiency through acceptance, not the target correction
rule. In finite-precision greedy experiments,
batched and token-wise target evaluation can choose different tokens when the
largest BF16 logits are tied. We therefore report both sequence agreement and
the target top-1 margin at every disagreement, distinguishing numerical ties
from larger kernel-path differences.

For target and draft cache sizes $M_t$ and $M_d$, native speculative decoding uses
$M_t+M_d$. If layer $\ell$ stores keys and values with precisions
$b^K_\ell,b^V_\ell$, the compressed draft cost is approximately
\begin{equation}
  \widehat M_d \propto T \sum_{\ell=1}^{L_d}
  H^{KV}_\ell d_{h,\ell}\left(b^K_\ell+b^V_\ell\right),
\end{equation}
plus one scale per token and KV head in our per-vector quantizer. Total saving is
$(M_d-\widehat M_d)/(M_t+M_d)$; it is necessarily smaller than the percentage
saved from the draft cache alone.

\section{Method}

\subsection{Draft-cache fake quantization}

For a key or value vector $x$, we use symmetric per-vector fake quantization,
\begin{equation}
  s(x,b)=\frac{\max_i|x_i|}{2^{b-1}-1}, \qquad
  \widehat x=s\,\operatorname{clip}\!\left(\operatorname{round}(x/s),
  -2^{b-1}+1,2^{b-1}-1\right).
\end{equation}
Only the draft KV state is quantized between cached decode steps. The target model
and verifier remain in BF16. This simulator measures the algorithmic
memory--acceptance tradeoff without conflating it with a particular packed-cache
kernel.

The evaluator performs one target and one draft prefill per prompt. Each draft
round starts from the retained draft prefix cache, while the target verifies the
proposal in one cached forward pass. Accepted states are committed and rejected
suffix states are cropped in place; neither model recomputes the long prefix.
Target-greedy references are generated once outside the timed configuration
loop. This cache-resident execution is essential at long context and prevents
prefix recomputation from dominating either memory or runtime measurements.

\subsection{Acceptance-aware sensitivity profiles}

We first evaluate a full-precision draft baseline. Then, for each selected layer
$\ell$, component $c\in\{K,V\}$, and candidate bit width $b\in\{4,8\}$, we
quantize only $(\ell,c)$ while leaving all other draft-cache entries in BF16. The
measured risk is
\begin{equation}
  \widehat r^{\mathrm{SD}}_{\ell,c,b}
  =\overline{\alpha_{\mathrm{BF16}}-\alpha_{\ell,c,b}},
\end{equation}
where $\alpha$ is the end-to-end speculative acceptance rate and the bar denotes
a paired mean over calibration prompts. Because a small profile can make harmful
quantization appear beneficial by chance, we also evaluate the one-sided
uncertainty-aware risk
\begin{equation}
  r^{\mathrm{SD,UCB}}_{\ell,c,b}
  =\max\left(0,\widehat r^{\mathrm{SD}}_{\ell,c,b}
  +1.96\,\mathrm{SE}(\alpha_{\mathrm{BF16}}-\alpha_{\ell,c,b})\right).
\end{equation}
As a smoother alternative to discrete greedy accept/reject events, we profile
the speculative acceptance mass
\begin{equation}
  A(p,q)=\sum_y\min\{p(y),q(y)\}=1-\mathrm{TV}(p,q),
\end{equation}
which is the expected one-step acceptance probability under the standard
stochastic speculative-decoding correction rule. We evaluate allocations from
both the paired acceptance-rate UCB and the paired acceptance-mass UCB; neither
surrogate is selected using held-out evaluation outcomes.
We additionally log
accepted tokens per verification round, top-1 match, acceptance mass,
Jensen--Shannon divergence, greedy target agreement, and the target top-1 margin
at the first disagreement.

\subsection{Ordinary quality versus speculative acceptance}

The same frozen draft model is profiled under a second downstream objective:
teacher-forced continuation quality without speculative decoding. For each
candidate we measure
\begin{equation}
  r^{\mathrm{LM}}_{\ell,c,b}
  =\mathbb{E}_t\!\left[
  D_{\mathrm{KL}}\!\left(p_{\mathrm{BF16}}(\cdot\mid x_{\leq t})
  \parallel p_{\ell,c,b}(\cdot\mid x_{\leq t})\right)\right].
\end{equation}
This paired design isolates the downstream objective: model, prompts, quantizer,
candidate bit widths, and memory budget are held fixed, while the allocation is
optimized either for ordinary LM quality or speculative acceptance. Each selected
allocation is then cross-evaluated under both objectives.

\subsection{Equal-memory mixed-precision allocation}

Given one-at-a-time risks $r^o$ for objective $o$, our transparent allocator uses
exact dynamic programming to solve the additive surrogate
\begin{equation}
  \min_{\{b^c_\ell\}} \sum_{\ell,c} r^o_{\ell,c,b^c_\ell}
  \quad \text{s.t.}\quad
  \frac{1}{2|\mathcal L|}\sum_{\ell\in\mathcal L,c} b^c_\ell=B,
  \qquad b^c_\ell\in\{4,8,16\}.
  \label{eq:allocation}
\end{equation}
Thus quality- and acceptance-optimized allocations consume exactly the same
profiled-layer bit budget $B$. We additionally compare against matched-memory
K-priority and V-priority heuristics (e.g., K8V4 and K4V8 for $B=6$). The
additive approximation is validated by running every allocation through the
complete cached decoding loops; it is not treated as the final performance
estimate.

\section{Experimental Setup}

We evaluate the target--draft pairs in Table~\ref{tab:model-pairs} using
WikiText-2 validation blocks, four draft proposals per verification round,
greedy target verification, and 16 generated tokens per prompt. The objective
matrix uses 32 held-out sequences, three shuffle seeds, contexts 512, 1K, and
4K, and profiled mean budgets $B\in\{6,8,10,12\}$. We separately repeat the
Qwen matrix on streaming C4 and compare 16- versus 64-prompt acceptance
calibration. Main profiles cover the top eight draft layers; an all-layer Qwen
run measures the larger attainable memory reduction. Domain-shift experiments
use GSM8K answers and HumanEval prompts, while PG19 supplies 16K--32K prefixes.
Cross-family evaluation includes Qwen2.5, Qwen3, Llama 3, OLMo 2, and SmolLM2.
We also vary the proposal length over $\gamma\in\{2,4,8\}$ to test whether
allocation rankings change as rejection wastes longer draft blocks. All pairs
are checked for tokenizer compatibility.

\section{Results}

\subsection{Keys are the fragile routing state}

Figure~\ref{fig:gaussian} perturbs all draft-cache keys or values with Gaussian
noise scaled to the clean activation standard deviation. At $\alpha=0.03$, key
noise reduces top-1 agreement with the clean draft to 0.617 and raises JS
divergence to 0.176. Value noise at the same magnitude retains 0.992 top-1 match
with JS divergence 0.0004. At $\alpha=0.1$, the corresponding top-1 matches are
0.109 for K and 0.953 for V. This large separation is consistent with routing
errors in $K$ changing $A$ in Equation~\ref{eq:attention} before values are read.

\subsection{Equal memory does not imply equal acceptance}

Figure~\ref{fig:equal-memory} isolates the core comparison at 1K context. K8V4
and K4V8 have identical average precision and save the same bytes, yet K8V4 wins
in five of six families and ties OLMo within 0.002. Across all contexts and held-out
distributions it wins 19 of 20 matched comparisons. The effect is largest for
Qwen2.5-3B/1.5B: acceptance improves from 0.282 to 0.594 at 1K and from 0.300 to
0.636 at 4K. K8V4 saves 61.7\% of the draft cache and 27.0\% of combined
target-plus-draft KV memory for this pair. Depending on model-size ratio, total
savings range from 10.5\% (SmolLM2) to 28.8\% (Llama).

The asymmetry persists outside the main setting. On two shuffled C4 seeds,
K8V4--K4V8 differences are $+0.185,+0.282$ for Qwen, $+0.010,+0.074$ for OLMo,
and $+0.026,+0.090$ for Llama. For Qwen at 8K and 16K, the differences remain
$+0.260$ and $+0.140$, respectively, although these exploratory long-context runs
contain only four and two prompts.

\subsection{The asymmetry transfers to mathematics, code, and long prefixes}

At the six-bit all-layer budget, K-priority remains close to native while
V-priority fails across held-out domains. On GSM8K answers, K8V4 exceeds K4V8 by
$22.72$ points at 512-token context (95\% CI $[19.34,25.90]$) and $25.18$
points at 1K (CI $[20.76,29.81]$); K8V4 itself is within $0.12$ and $0.09$
points of native acceptance. On HumanEval prompts, the corresponding K8V4--K4V8
gaps are $27.03$ points at 256 tokens (CI $[21.22,33.26]$) and $32.93$ points
at 512 (CI $[27.32,38.48]$). The HumanEval aggregate contains no non-tie target
disagreements.

The separation grows with long PG19 prefixes. At 16K, K-priority is $1.03$
points below native (CI $[-4.47,2.14]$), while V-priority is $44.76$ points
below native (CI $[-52.50,-38.14]$), giving a paired K-priority advantage of
$43.73$ points (CI $[37.07,51.28]$). At 32K, K-priority is $3.37$ points below
native (CI $[-6.89,-0.17]$), while V-priority drops by $55.51$ points; their
paired difference is $52.13$ points (CI $[43.22,61.73]$). Both contexts use two
seeds and contain no non-tie target disagreements.
These results indicate that routing precision becomes more, rather than less,
important as each query chooses among a longer cached prefix.

A fixed-key value-precision sweep identifies a sharp knee below four bits. Across
three 1K-context seeds, K8V4 saves $27.00\%$ of total target-plus-draft KV memory
with an acceptance change of $-0.96$ points (CI $[-2.22,0.26]$). K8V3 increases
savings to $28.37\%$ but incurs a small significant drop of $1.74$ points
(CI $[-3.30,-0.20]$), while K8V2 collapses by $24.67$ points. We therefore use
K8V4 as the conservative operating point and treat K8V3 as an aggressive option.
The same knee holds across three 4K-context seeds: K8V4 changes acceptance by
$-0.16$ points (CI $[-1.53,1.17]$), K8V3 drops $2.14$ points
(CI $[-3.95,-0.35]$), and K8V2 drops $24.88$ points.

\subsection{A conservative learned allocation}

Profiling the top eight draft layers and selecting precision under a five-point
additive acceptance budget gives deliberately conservative allocations. Across
the six pairs, held-out acceptance retention ranges from 94.9\% to 102.8\%, while
total KV savings range from 2.9\% to 9.9\%. Figure~\ref{fig:pareto} shows that
uniform K4V4 often saves more memory but can retain less than half of native
acceptance; the sensitivity-aware solutions stay near the 100\% line.

\subsection{Objective-specific profiles differ, but do not improve acceptance consistently}

Optimizing the sensitivity profile under the speculative loop is not reliably
better than profiling ordinary language-model quality. In a powered Qwen
replication with 384 held-out prompts, the acceptance-mass allocation changes
several layer-wise K/V assignments but trails the quality allocation by $0.94$
percentage points (95\% CI $[-1.76,-0.14]$). The corresponding effects are
$-1.74$ points for Llama (CI $[-4.47,0.86]$) and $-0.10$ points for OLMo
(CI $[-2.49,2.33]$). Under the more aggressive three-bit mean budget on Qwen,
acceptance optimization is significantly worse by $4.93$ points
(CI $[-7.29,-2.64]$).

These results reject the strongest version of our initial hypothesis: directly
optimizing a small calibration set for speculative acceptance is not sufficient
to discover a better held-out allocation. Greedy acceptance is discrete and
high variance, while the additive allocator ignores interactions among jointly
quantized components. In contrast, quality profiling repeatedly recovers the
stable K-first solution and has lower held-out KL. We therefore treat downstream
acceptance as the evaluation criterion, but not yet as a proven superior training
objective.

\subsection{Finite-precision verification audit}

The target cache and weights remain BF16 and are never quantized. Nevertheless,
multi-token verification and tokenwise greedy decoding invoke different GPU kernel
shapes. Across 2,010 prompt--configuration outputs, 308 sequence disagreements
occur where either target path has top-1 margin at most $10^{-3}$, and 33 (1.64\%)
remain above that threshold. Focused diagnostics found no causal-mask leakage and
no causal-suffix violation. BF16 SDPA reproduces one speculative mismatch on each
of four independent non-tie prompts, whereas FP32 SDPA produces zero on all four.
Two BF16 traces also show rollback-path top-1 flips, but these disappear in FP32;
on an additional traced prompt, switching BF16 from SDPA to eager attention also
eliminates the mismatch. This backend and precision dependence supports
finite-precision kernel-path drift rather than stale-cache corruption. We
consequently do not claim bitwise
equality to tokenwise BF16 greedy decoding, while the target verification rule
itself remains unquantized.

\subsection{Motivating negative result: direct cross-model cache maps}

Our earlier approach attempted to replace parts of the draft cache with linear
maps from target-model KV states. Sharing the top four of 28 draft layers reduced
total KV memory by only 6.25\% and reduced acceptance from 0.497 to 0.455 in the
cached-quality benchmark. Sharing every layer degraded acceptance much more. This
failure motivated the current direction: preserve each model's native cache
semantics, compress the cheaper draft state, and optimize the quantity that
matters for speculative decoding. Concurrent work on cross-model prefill reuse
also finds that transfer quality depends strongly on error placement and often
benefits from RoPE removal, cross-layer selection, or nonlinear maps
\citep{heo2026crossmodel}.

\section{Related Work}

KIVI establishes that key and value caches have different outlier structures and
uses per-channel K and per-token V quantization~\citep{liu2024kivi}.
KV-AdaQuant argues for allocating more precision to keys based on norm and
quantization sensitivity~\citep{hariri2025more}. Our work does not claim that K/V
asymmetry is new; it tests and optimizes that asymmetry under speculative
acceptance, where a single changed proposal can truncate an entire draft block.

QuantSpec combines self-speculative decoding with a hierarchical 4-bit KV
cache~\citep{tiwari2025quantspec}. QSpec combines complementary model
quantization schemes and reuses model state between drafting and verification
\citep{zhao2025qspec}. In contrast, we study standard two-model speculative
decoding and allocate draft-cache precision by measured acceptance sensitivity.

\section{Limitations and Next Experiments}

The present quantizer uses per-vector symmetric fake quantization. It does not yet
implement packed storage, residual windows, per-channel key grouping, or fused
attention kernels; therefore analytical cache bytes, not wall-clock latency, are
the reliable systems metric. Although the campaign spans six pairs and includes
two C4 seeds for three pairs, prompt counts remain modest at 16K--32K and on
task-conditioned code and mathematics prompts. Broader LongBench evaluation and
larger PG19, HumanEval, and GSM8K samples are needed. Our BF16 audit also shows
that mathematically distribution-preserving
speculation need not be bitwise identical to tokenwise decoding across kernel
shapes; higher-precision and production-kernel audits remain important.

The additive allocation in Equation~\ref{eq:allocation} ignores interactions
between compressed components. We plan to fit a small risk predictor over joint
allocations and compare it against uniform precision, KIVI-style quantization,
KV-AdaQuant, QuantSpec, and random allocations at matched memory. A packed-cache
kernel in vLLM or SGLang is required before making end-to-end throughput and
serving-capacity claims.

\section{Conclusion}

Draft KV compression should be evaluated by the speculative work it preserves,
not reconstruction error alone. Across six model pairs, K8V4 wins 19 of 20
equal-memory comparisons, showing that keys are acceptance-critical routing state
while values usually tolerate more aggressive compression. Conservative K-first
allocations preserve near-native draft behavior, and the Qwen results show that
substantially larger savings are possible. Direct acceptance-trained allocation
does not yet improve reliably over quality profiling, exposing calibration noise
and component interactions as important open problems. These findings motivate
packed asymmetric kernels and better interaction-aware allocation evaluated by
speculative acceptance rather than reconstruction error alone.
