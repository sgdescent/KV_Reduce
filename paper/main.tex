\begin{abstract}
Speculative decoding reduces generation cost, but it stores two KV caches: one
for the target model and one for the draft model. We reduce this extra memory by
quantizing the draft cache. The target cache and verifier remain in BF16, so that compression cannot change the target model's final
correction rule. We first study how
to divide precision between keys and values. A naive per-token quantizer makes
keys appear much more sensitive: splitting a 12-bit budget, K8V4 beats K4V8 in acceptance by 10.87~pp. However, with grouped
per-channel keys, the gap becomes $-0.25$~pp. A controlled Qwen test confirms
that changing only the key quantizer can erase or reverse the preferred bit
split. Hence, following KIVI, we propose K4V4 quantization with per-channel keys and per-token values. Across six model pairs, our method reduces draft cache memory by 66.20\%, and combined memory across both caches by 23.95\%. Mean acceptance drops from 57.93\% to 57.14\%, only 1.36\% relative. Overall, quantized draft caches can make speculative decoding more memory efficient; as a predictive principle for efficient AI design, key and value precision must be co-designed with the quantizer layout.
\end{abstract}

\section{Introduction}

Speculative Decoding (SD) improves LLM inference latency by letting a small \emph{draft} model propose tokens that a larger \emph{target} model verifies in parallel~\citep{leviathan2023speculative,
chen2023speculative}. Draft tokens are accepted sequentially until the first rejection, at which point a corrected token is sampled from the target model and generation continues from there. This maintains the target output rule while reducing the number of expensive target forward passes.

However, standard SD maintains a KV cache for each model, increasing memory pressure as context length and batch size grow. Let $\text{Mem}_T$ and $\text{Mem}_D$ be the target and draft cache sizes.
Standard SD stores $\text{Mem}_T+\text{Mem}_D$. We instead store $\text{Mem}_T+\widehat \text{Mem}_D$,
where $\widehat \text{Mem}_D$ is the low-precision draft cache size. Note that the target cache remains unchanged. Quantization may reduce draft model acceptance, but it will not affect target model performance.

The main design question is how to quantize keys and values. Attention computes $O=AVW_O$ with $A=\operatorname{softmax}(QK^\top/\sqrt{d_h}+M)$~\citep{vaswani2023attention}. Keys control where we read, while values contain the information returned by reads. Empirically, it is tempting to conclude that keys
always need more precision because they are more sensitive to noise. For example, under Gaussian noise with standard deviation 0.03 times the per-layer RMS, key noise reduced top-1 agreement to 61.7\%, while value noise retained 99.2\%.

We organize our study around three research questions. \textbf{(1) Key and value precision.} Is the apparent need for higher key precision intrinsic to attention, or is it caused by quantizer geometry and outlier handling? \textbf{(2) Memory and acceptance.} How much SD memory can draft-only KV cache quantization save without materially reducing token acceptance? \textbf{(3) Generalization and practical savings.} Do these memory-quality tradeoffs hold across model families, long contexts, and retrieval workloads, and do they translate into real packed-storage savings?

\section{Related Work}

In standard autoregressive inference, KV cache quantization successfully mitigates memory costs, though precision allocation is often heuristically driven. For example, KIVI applies an asymmetric strategy of per-channel quantization for keys and per-token quantization for values \citep{liu2024kivi}, whereas Quantize What Counts argues for allocating higher precision to keys based on the distinct geometries of key and value representations \citep{hariri2026quantize}. Other approaches optimize bit allocation dynamically: KVTuner searches for layer-wise precision pairings \citep{li2025kvtuner}, RateQuant distributes bits across attention heads via rate-distortion theory \citep{zuo2026ratequant}, and RoPE-Aware techniques allocate precision across frequency blocks \citep{liang2026blockgtq}. We build on KIVI's geometry and study asymmetric bit splitting (e.g., K8V4 vs. K4V8) in conjunction with it.

While QuantSpec introduces hierarchical KV quantization for self-speculative decoding \citep{tiwari2025quantspec}, our work addresses a different paradigm. We study standard two-model speculative decoding, specifically targeting the quantization of the draft model's cache. By evaluating the trade-off between total memory savings and candidate acceptance rates, we isolate how key-quantizer geometry alters conclusions about the optimal precision balance between keys and values.

\section{Draft Cache Quantization}

Let K$a$V$b$ denote $a$-bit keys and $b$-bit values. We first compare K8V4 against K4V8 to test whether keys or values need more bits. Our simple baseline uses one symmetric scale for each token and KV head. For a
$b$-bit group $G$, symmetric scale $s_G$ is computed as follows:
\begin{equation}
 s_G=\frac{\max_{x\in G}|x|}{2^{b-1}-1},\qquad
 \widehat x=s_G\operatorname{clip}(\operatorname{round}(x/s_G)).
 \label{eq:symmetric}
\end{equation}
This baseline lets channel-specific key outliers set the scale for the full
vector. Inspired by KIVI, our layout instead uses 32-token per-channel key groups
and per-token affine value groups within each head~\citep{liu2024kivi}, as
shown in Figure~\ref{fig:quantizer-geometry}. Section~\ref{sec:results} tests this choice. Keys also use affine groups, and the 128 most recent keys stay in BF16 (Appendix~\ref{app:protocol}). We count payload bits, BF16
scales, zero-points, and the BF16 residual window in every memory result.

The target verifier also remains in BF16. We measure draft-token acceptance,
KL from BF16 draft logits, top-1 agreement, and retrieval accuracy.

\section{Evaluation}

We test six target and draft pairs across Qwen2.5~\citep{yang2024qwen25},
Qwen3~\citep{yang2025qwen3}, Llama 3~\citep{grattafiori2024llama3}, OLMo
2~\citep{olmo2025furious}, and SmolLM2~\citep{allal2025smollm2}. Model sizes
range from 360M to 8B parameters. We evaluate 576 FineWeb-Edu prompts (96 per
pair)~\citep{penedo2024fineweb} with greedy decoding. The draft proposes up to four
tokens per round, and each run generates 16 tokens. Every prompt is tested with BF16,
K8V4, K4V8, and K4V4. The noise test, the RQ1 acceptance comparisons, and the
KL and top-1 measurements use WikiText-2 validation text
instead~\citep{merity2016pointer}.

With the Qwen2.5 3B/1.5B pair, we keep the models, prompts, value quantizer, and bit budget fixed, and change only the key quantizer. We also run 192 paired passkey examples at 16K context. Finally, we test 256-token continuations and an end-to-end packed prototype with the same pair at 1K and 16K context (Appendix~\ref{app:followup}). Full
model details and confidence interval procedures are in
Appendix~\ref{app:protocol}.

\section{Results}
\label{sec:results}

\subsection{RQ1: Are keys intrinsically more precision-sensitive?}

We demonstrate that the apparent need for higher key precision depends strongly on quantizer geometry, and is not necessarily an intrinsic property of attention. When using a naive per-token symmetric quantizer, keys appear highly sensitive: K8V4 outperforms an equal-mean-bit K4V8 by 10.87~pp on average. However, switching to grouped per-channel keys eliminates this advantage, shifting the contrast to $-0.25$~pp and dropping all within-pair gaps below 1~pp (Figure~\ref{fig:geometry}a).

A controlled Qwen intervention, which strictly isolates the key quantizer, confirms this behavior. Changing the key geometry shifts the K8V4 versus K4V8 gap from $+28.70$ to $-0.33$~pp, and reverses the aggressive K4V2 versus K2V4 contrast from $+15.05$ to $-3.66$~pp. This interaction extends to 16K retrieval tasks (Figure~\ref{fig:geometry}b), where modifying key geometry shrinks the K4V2 versus K2V4 accuracy gap from 81.25 to 16.15~pp. Ultimately, bit width and quantizer geometry must be co-designed; keys do not universally demand more precision. Appendix~\ref{app:geometry} contains more details.

\subsection{RQ2: How much memory can draft-only quantization save?}

Using K4V4 as our balanced operating point, we find it removes about two-thirds of draft cache memory. Across all six evaluated model pairs, K4V4 reduces draft cache bytes by 66.20\% and the combined target-plus-draft KV memory by 23.95\% (11.30\% to 33.17\% across pairs).

Importantly, this compression incurs minimal degradation to candidate generation. The mean cross-family acceptance rate falls only from 57.93\% to 57.14\%, a 1.36\% relative drop (Figure~\ref{fig:memory-acceptance}a). In separate WikiText-2 runs, the K4V4 draft's KL from BF16 is 0.00730 (95\% CI $[0.00660,0.00801]$), with 95.99\% top-1 agreement. With 256-token continuations on one Qwen2.5 pair, the acceptance change ranges from $-0.59$ to $+0.33$~pp, and the outputs match target-only greedy decoding under a sequential verifier (Appendix~\ref{app:followup}).

\subsection{RQ3: Does the result generalize and produce real savings?}

The memory-quality tradeoffs of K4V4 hold across six model pairs and extended context windows. At 16K and 32K context with the Qwen2.5 3B/1.5B pair, K4V4 reduces combined KV memory by about 31\%, with mean acceptance drops of only 0.94 and 0.73~pp, respectively (Appendices~\ref{app:geometry} and~\ref{app:retrieval}).

The analytical byte savings also hold in physical packed storage. At 32K context, a standard Qwen2.5-1.5B BF16 cache requires 896.0 MiB per sequence, whereas our packed K4V4 implementation consumes just 260.2 MiB, saving 635.8 MiB (Figure~\ref{fig:memory-acceptance}b). However, these savings do not yet translate into a serving benefit. In an end-to-end prototype with the same pair at 1K and 16K context, packed K4V4 stores 67\% to 71\% fewer draft cache bytes, but it is 18\% to 33\% slower than BF16 speculative decoding, which is slower than target-only decoding. Peak GPU memory is also unchanged, since the draft cache is packed only after a BF16 prefill. Its batched verifier reproduces target-only outputs on only 2 to 5 prompts per setting (of 12 or 24), even with a BF16 draft, so we treat these timings as preliminary (Appendix~\ref{app:followup}). Appendix~\ref{app:objectives} covers policy selection.


\section{Discussion}

\textbf{Conclusion.} Our results show that draft-only KV cache quantization can substantially reduce
the KV cache memory overhead of two-model speculative decoding while largely preserving draft
acceptance. K4V4 removes about two-thirds of draft cache memory, while
the target verifier and its correction rule remain unchanged. The results also
show that key and value precision cannot be evaluated independently of
quantizer geometry,
providing a predictive principle for the design of future quantization systems.

\textbf{Limitations.} Our longest-context experiments have fewer prompts than the 1K study. The
retrieval task is partly synthetic. Fake quantization measures quality but not
production speed. Our packed prototype is still slower than BF16
speculative decoding and does not yet lower peak GPU memory, so we do not claim an end-to-end speedup. The 256-token and prototype experiments cover one model pair at batch size one, and the batched verifier, which the RQ1 acceptance comparisons also use, is not yet exact. We do not measure key outliers directly, and keys and values may differ intrinsically in settings we do not test.

\textbf{Future work.} Future work could replace static bit assignments with serving-time adaptive
computation, building predictive models for runtime quantization that select key and value precision by layer, context region, or
request. Realizing this approach
will also require an exact batched verifier, streaming prefill, fused packed-cache attention kernels, and end-to-end evaluation
in production inference systems.

\paragraph{Decoding protocol.}
All speculative decoding experiments use greedy decoding at batch size one. In
each round, the draft proposes up to four argmax tokens. The target accepts the
longest proposal prefix that matches its own argmax tokens. The target
then emits a correction token at the first disagreement, or a bonus token after
a fully accepted proposal. We crop the draft cache to the committed prefix, which
discards rejected entries, and append the emitted token to both caches.
Generation has a fixed length without early stopping. Acceptance excludes
correction and bonus tokens. The sequential verifier advances the target one
accepted token at a time and makes one target call per emitted token, so it
measures draft quality but not target-call savings. The batched verifier scores
a proposal in one target call and rolls the target cache back. Tables~\ref{tab:app-geometry} and~\ref{tab:app-factorial}, the Spearman grid,
and the prototype use the batched verifier; all other speculative results use
the sequential verifier.

\paragraph{Quantizer geometries.}
The simple quantizer (Equation~\ref{eq:symmetric}) uses one scale for each
token and KV head, for keys and values. The stronger
quantizer uses KIVI's per-channel key and per-token value geometry
\citep{liu2024kivi} with affine groups (Equation~\ref{eq:affine}). In our implementation, keys are grouped over 32 tokens,
values are grouped within each token and head, and the newest 128 key tokens
remain in BF16. In the controlled test, we remove this residual window and
change only the key quantizer (per-token symmetric versus per-channel
affine). We never update model weights.

\paragraph{Quantizer specification.}
An affine $b$-bit group $G$ has zero-point $m_G=\min_{x\in G}x$ and scale $s_G$:
\begin{equation}
 s_G=\frac{\max_{x\in G}x-m_G}{2^{b}-1},\qquad
 \widehat x=m_G+s_G\operatorname{clip}\big(\operatorname{round}((x-m_G)/s_G),\,0,\,2^{b}-1\big).
 \label{eq:affine}
\end{equation}
Consider one layer with keys and values of shape $H\times L\times d$, with $H$
KV heads, $L$ committed tokens, and $d$ channels. We use K$a$V$b$ with group
size $g=32$ and residual length $R=128$. For keys, we set
$P=g\lfloor\max(0,L-R)/g\rfloor$. A key group covers one head, one channel, and
$g$ consecutive tokens. We apply Equation~\ref{eq:affine} with $a$ bits to each
newly completed group below $P$. Tokens at or beyond $P$ remain in BF16, and we
never pad or requantize incomplete groups. For values, we apply
Equation~\ref{eq:affine} with $b$ bits to the $d$ channels of each new token and
head. Values have no residual window. During a speculative round, $P$ is
frozen, so we only quantize committed keys. We compute statistics in FP32 and
floor ranges at $10^{-8}$. We round to nearest with ties to even. The
symmetric baseline clips to $\pm(2^{b-1}-1)$. Quality experiments use fake
quantization, which writes dequantized tensors back into the BF16 cache and
computes bytes analytically. The packed implementation stores two 4-bit payload
entries per byte in row-major \texttt{uint8} tensors. Metadata and residual
keys remain in BF16.

\paragraph{Byte accounting.}
We count packed payloads, BF16 scales, zero-points, and the BF16 residual window.
Let $\text{Mem}_T$ be the target cache, $\text{Mem}_D$ be the native draft cache, and
$\widehat \text{Mem}_D$ be the quantized draft cache. Total memory saving is
\begin{equation}
  \operatorname{saved}_{\mathrm{total}}
  =1-\frac{\text{Mem}_T+\widehat \text{Mem}_D}{\text{Mem}_T+\text{Mem}_D}.
\end{equation}
The draft cache shrinks by 66\% to 71\%, depending on experimental factors. The target cache does not shrink, so the combined saving across both caches is smaller.
For each pair, the total saving equals the draft saving times the draft's share
of the combined BF16 cache (Table~\ref{tab:app-k4v4-generalization}). All
savings refer to KV cache bytes, not model weights or activations.

\paragraph{Metrics and uncertainty.}
Acceptance is the fraction of proposed draft tokens accepted by the target.
Acceptance differences are absolute, in percentage points (pp), unless marked as relative.
We also measure KL from the BF16 draft, top-1 agreement, and exact retrieval
accuracy. KL is $\mathrm{KL}(p\,\|\,q)$, where $p$ and $q$ are the draft's
next-token distributions with a BF16 and a quantized cache on teacher-forced
continuations. We average it over positions and prompts, and then equally over
model pairs. Top-1 agreement is the fraction of these positions with the same
argmax.
Confidence intervals are paired bootstrap intervals over prompts with 5,000 to
30,000 resamples. The macro of Table~\ref{tab:app-k4v4-generalization} resamples
pairs and then prompts; other cross-model averages resample pairs only.

\paragraph{Verifier audit.}
The target still checks every proposed token, so draft quantization does not
change the mathematical correction rule. We compare every speculative output
with an independent tokenwise target path and call a mismatch a near tie when
the target's top-1 margin is at most $10^{-3}$. All sequential-verifier
trajectories match, including 38,400 checks in Appendix~\ref{app:objectives}.
With the batched verifier, Table~\ref{tab:app-factorial} and the grouped-key
column of Table~\ref{tab:app-geometry} drop prompts with non-tie mismatches;
Table~\ref{tab:app-geometry}'s per-token column keeps them (one to three prompts
in four of its twelve runs). A BF16 target
cache preserves the correction rule, but it does not guarantee bit-identical
outputs from a batched verifier.

With the Qwen2.5 3B/1.5B pair on FineWeb-Edu, we also test key groups of 16, 32, 64, and 128 tokens. The K4V2

the 16-token interval excludes zero. We test BF16 residual windows of 0, 32, 128, and
256 tokens as well. A longer window gives no clear K4V4 acceptance gain.
Removing it increases draft cache saving from 66.33\% to 70.56\%.
Our 256-token experiments also show no clear acceptance gain from the window
(Appendix~\ref{app:followup}), so we treat 128 tokens as a configuration
choice rather than an optimum.

\section{Memory Implementation}
\label{app:systems}

\paragraph{Packed storage.}
Figure~\ref{fig:memory-acceptance}b uses a real packed cache with
\texttt{uint8} payloads, BF16 metadata, and a BF16 residual window. The measured
tensors use 28 layers, two KV heads, and head dimension 128. This confirms that
the estimated saving we report is present in stored tensors rather than only in
theoretical bit counts. At 32,768 tokens, the 896.00 MiB BF16 cache becomes
260.20 MiB. Keys take 111.56 MiB of 4-bit payload, 27.89 MiB of BF16 scales and
zero-points, and 1.75 MiB for the BF16 residual window. Values take 112.00 MiB
of 4-bit payload and 7.00 MiB of BF16 scales and zero-points. This metadata costs
$2\cdot 16/32=1$ bit per quantized key element and $2\cdot 16/128=0.25$ bits
per value element, so a 4-bit payload does not give a 75\% saving. The packed cache
needs no padding or alignment bytes. We exclude temporary kernel workspace.

\paragraph{Kernel diagnostic.}
A Triton prototype reads the packed cache without first rebuilding a full BF16
cache. At 32K, it takes 0.708 ms per layer. Rebuilding the cache first takes
1.448 ms. Native BF16 SDPA takes only 0.103 ms. The prototype proves that packed
attention is possible, but it does not yet provide an end-to-end speedup.

\paragraph{Correctness.}
With the sequential verifier, all 576 evaluations of the quality study (six
settings, four configurations, and 24 prompts) reproduce target-only greedy
decoding exactly. All 94 sequential audits recorded in the packed runs also
pass. The batched verifier behaves differently. At 1K, it matches target-only
greedy decoding on 3, 4, and 5 of 24 sequences for BF16, residual 0, and
residual 128. At 16K, it matches on 2 of 12 sequences for each configuration. A
mismatch means that at least one token differs. The BF16 baseline also
mismatches, so quantization alone cannot explain the difference. We have not
yet found the cause, and we do not assume that the mismatches are harmless near
ties, so we treat the timings as preliminary. The timings also come from a
shared node and one model pair. We do not measure production throughput,
maximum batch size, or concurrent serving.

\section{Choosing a Precision Policy}
\label{app:objectives}

We ask whether precision should be chosen using speculative acceptance or
ordinary draft quality. Over 20 uniform K/V settings of Qwen2.5 3B/1.5B on
WikiText-2, the two have Spearman correlation 0.964 at 1K and 0.878 at 4K. For five
pairs on FineWeb-Edu, equal-byte per-layer allocations built from each measure
coincide at mild budgets. At a three-bit budget, the acceptance-profiled choice is 0.48~pp worse
(95\% CI $[-0.98,-0.05]$) and has higher KL. Direct
acceptance is still the final serving metric, but we do not find a benefit from
an acceptance-only allocator.

\section{What We Do Not Claim}
\label{app:scope}

\begin{itemize}
  \item We do not claim that one key and value bit split works for every model.
  \item We do not claim faster kernels or decoding, or lower peak GPU memory.
  \item We do not claim that the 128-token residual window improves acceptance.
  \item We do not claim that our results hold under stochastic sampling.
  \item We do not quantize the target cache in the main method.
  \item We treat BF16 near ties separately from true target mismatches.
  \item We reject incomplete runs before computing aggregate results.
\end{itemize}
